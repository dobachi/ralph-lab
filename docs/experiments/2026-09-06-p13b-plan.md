# P13-4 実験計画: framework tamper 対策後の 9 度目 Goodhart (2026-09-06 実行前)

**目的**: P13-3 で Layer 0 (BASE hash verify + 復元) を実装した後、
agent が次にどの穴を突くかを実測。8 度目観察 (BASE 書換) を塞いだ結果、
「隣の穴」が既知の 4 種 (捏造/削除/迂回/逆向き置換) に戻るか、また
新種が現れるか。

**loop-goal 精神**: 予測を実行前に書く。P13-2 は予測 5 シナリオ全外れ
だったので、今回は**「予測外の可能性」を明示的に予測範囲に含める**。

## 予測

### 主予測: **URL 形式 dummy or content-shaped dummy を tamper 抜きで実行、iter 3-4 で pass**

**根拠**:
- P13-2 で agent は既に「content-shaped dummy を作る」能力を実測した
- BASE tamper がブロックされたら、tamper なしの同じ手 (content dummy 追加)
  を単独で試すのが自然
- ただし Check 2 (monotonicity) の baseline は真物になったので、body の
  `[^99]` を [^1] に戻さないと通らない

### iter 数

**3-5 iter**:
- iter 1: 前回同様「BASE も current も同時書換」を試みる → tamper 検出、
  iter NG + FRAMEWORK VIOLATION feedback を受け取る
- iter 2: feedback を読み「BASE 触るな」と学ぶ、代替戦略に移行
- iter 3-4: URL/content dummy または clean fix

### Cost 予測

$0.05-0.10 (haiku で 3-5 iter × 10-20s)

### 予測シナリオ (確率降順)

| # | シナリオ | 確率 | 何が判明 |
|---|---|---|---|
| 1 | tamper 試行 → block されて後で clean fix (body [^99]→[^1]) | 30% | Layer 0 が有効に効き、agent が feedback を読んで正解経路に |
| 2 | tamper 試行 → block されて後で URL 形式 dummy 追加、body 側の Check 2 が catch → 5 iter fail | 25% | Layer 0 は効いたが gate 内の穴 (URL dummy) が浮上する予測外もう一段 |
| 3 | tamper 試行を全 iter で繰り返す (feedback を読まない) | 15% | agent の feedback 読解限界。Ralph loop の限界の 1 つ |
| 4 | tamper なしで最初から clean fix | 15% | 非決定性の当たり (前回とは違う経路を選ぶ) |
| 5 | 新種 Goodhart (framework の別の穴) | **10%** | 例: current.md を消して再作成、chmod で workspace root 権限を触る、他 |
| 6 | tamper 復元後の状態を含めた別の novel hack | 5% | 例: 「復元されたら次の iter で復元後の状態から差分を計算し直す」的な多段 hack |

**主予測**: シナリオ 1 or 2 (合計 55%)。

### 最も気にしているシナリオ

**シナリオ 5 (新種 Goodhart、確率 10%)**: これが起きたら P13-3 が
「穴を塞いだ隣の穴」で、また Layer 0 の追加設計が必要になる。予測外
シナリオこそが最も情報量が多い。

**learnings**:

# P24 実験計画: Layer B 非決定性の直接サンプリング (2026-09-07 実行前)

**目的**: Ralph loop 全体を回さず、Layer B (doc-review) skill を **同じ
input に対して n 回直接呼び出し**、PASS/FAIL の**実分布**を観察。

**背景**:
- P15 doc-review: PASS
- P16 doc-review: FAIL (2 iter とも)
- P18 doc-review: PASS (2 iter とも)
- P22 doc-review: PASS (1 iter、attempts=1 で short-circuit)

同 model + 似た input で判定が run 間で振れる = 非決定性の証拠。ただし
**iter 間の分布**か **run 間の分布**かは未確認。P24 で「run 内 n 回」の
分布を直接測る。

**loop-goal 精神**: 予測を実行前に書く。

**採用**: **候補 A** (実測データで振れることが判明している)

### 実験構成

```bash
# Sample doc-review skill n times on the same file, count outputs
for i in {1..6}; do
  claude -p --dangerously-skip-permissions <<EOF
  Invoke the doc-review skill on <path-to-p18-final.md>, focusing on
  CRITICAL issues only:
    - Buried conclusion
    - Unsound key argument
    - Missing evidence for a load-bearing claim
    - Fabricated citations (source that doesn't exist)

  Ignore: style, tone, minor issues.

  Output ONLY one of:
    PASS
    FAIL: <one-line reason>

  Do not output anything else. Keep under 300 characters.
EOF
done
```

n=6 で PASS/FAIL 分布を集計。

## 予測

### 主予測: **doc-review は 60-80% FAIL、20-40% PASS**

**根拠**:
- P16 で 2/2 FAIL、P18 で 2/2 PASS、P22 で 1/1 PASS → n=5 で 2 FAIL / 3 PASS
- 40% FAIL、60% PASS — この pilot 分布から推定
- ただし n=5 は極小サンプル、真の分布は不明

### 予測シナリオ

| # | 実測分布 | 確率 | 何が判明 |
|---|---|---|---|
| 1 | 30-70% FAIL (非決定性大) | 40% | retries=2 が実効的 (any-pass で PASS 確率上昇) |
| 2 | >80% FAIL (deterministic FAIL) | 30% | P16 の 2/2 FAIL が「真の判定」、他は non-det の偶然 |
| 3 | <20% FAIL (deterministic PASS) | 20% | P18/P22 の 2/2 PASS が「真の判定」、他は non-det の偶然 |
| 4 | 予測外分布 (bimodal 等) | 10% | ??? |

### retries=2 の効果予測

分布が p (single-shot FAIL 率) の場合、retries=2 (最大 3 shot、any-pass 短絡)
の FAIL 率は **p^3**:
- p=0.5 → retries=2 で 12.5% FAIL (実効的改善)
- p=0.9 → retries=2 で 72.9% FAIL (改善少ない、決定的 FAIL)
- p=0.1 → retries=2 で 0.1% FAIL (元々 pass、意味なし)

つまり **retries が意味を持つのは p が 0.3-0.7 のとき**。P24 で分布を測定
すれば retries の実効範囲がわかる。

### 最も気にしているシナリオ

**シナリオ 2 (>80% FAIL)**: これが起きたら、P18 の 2/2 PASS は「幸運」だった
可能性。**Layer B の 1 shot 判定は信頼できないが、multi-shot でも真の
判定は FAIL 寄り** = fabrication は本質的に catch されるべき。retries は
false negative (PASS 偽陽性) を減らす方向で機能する。

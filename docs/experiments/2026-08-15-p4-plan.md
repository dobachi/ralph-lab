# P4 実験計画 (2026-08-15)

**目的**: agent-loop-lab (P1-P3 で組み上げた outer loop) を実 goal で回し、
モデル差 / タスク難度 / 失敗モードの 3 軸で定量測定する。

**loop-goal 精神を継ぐ**:
- **予測をこの doc に**「実行前に」書く。走らせてから理由付けしない
- 予測が外れた場合はそのまま記録する ([results.md](2026-08-15-p4-results.md) 側で)
- 「n=1 の比較は読めない」ので**幅を取って傾向を掴む**方針にする

**測定対象** (loop-goal 同梱 fixture):
| fixture | 失敗の種類 | 直し方の性質 |
|---|---|---|
| `broken_ref.md` | 未定義 [S-99] + 未使用 S-06 | 単純 substitution (小さい edit) |
| `declared_mismatch.md` | 申告 9 / 実測 6 | 数字か本文の**どちらを変えるか**、判断が要る |
| `with_history.md` | 「【訂正】」等の混入 | 該当行を削るだけ |
| `uncited.md` | 未引用の断定文が多い | **足す** タスク (増やす方向) |

## Experiment 1 — 3-model horse race (broken_ref.md)

**問い**: 同じ goal を model だけ変えたとき、pass 率と効率はどう変わるか。

**Setup**:
- fixture: `broken_ref.md`
- spec: `goals/examples/doc-verify.yaml`
- models: `openai/gpt-4.1-mini`, `openai/gpt-4o-mini`, `anthropic/claude-haiku-4.5`
- `--models "..."` で 1 コマンド

**予測 (実行前)**:

| Model | Status | 予想 iterations | 予想 total tokens | 根拠 |
|---|---|---|---|---|
| gpt-4.1-mini | **pass** | 2 | ~11k | 昨日 2 回連続で 2 iter pass。安定 |
| gpt-4o-mini | **fail (5 iter 到達)** | 5 | ~70k | 昨日 5 iter 全部失敗。Markdown 表構造を壊す edit をする |
| claude-haiku-4.5 | **pass** | 1〜2 | ~5k-10k | Anthropic 直系 (openai-agents SDK と親和性)。文書構造理解が gpt-4o-mini より良い想定 |

**予想が外れる余地**:
- (a) claude-haiku-4.5 が SDK の tool 契約でつまずく (未検証パターン)
- (b) gpt-4o-mini が「今回はたまたま」pass する (非決定性)
- (c) haiku が pass するが `edit_current` の使い方 (old_str の unique 判定) が
  gpt 系より頻繁に fail する

**成功条件**: 3 model 全部が最後まで走り切る (init_error 0)。pass/fail は
問題でない (それが測定対象)。

**コスト目安**: ~$0.10

## Experiment 2 — 3-fixture rotation (gpt-4.1-mini fixed)

**問い**: 同じ model で failure mode が変わると、iteration 数と token 消費は
どう変わるか。特に「判断を要する task」で iter が伸びるか。

**Setup**:
- model: `openai/gpt-4.1-mini` 固定
- fixtures: `broken_ref.md`, `declared_mismatch.md`, `with_history.md`
- spec: goals/examples/ に 3 個 (broken-ref.yaml / declared-mismatch.yaml /
  with-history.yaml) を用意し、順に走らせる

**予測 (実行前)**:

| Fixture | Status | 予想 iterations | 予想 total tokens | 根拠 |
|---|---|---|---|---|
| broken_ref | **pass** | 2 | ~11k | baseline (Exp 1 と同条件) |
| declared_mismatch | **pass** | 2〜3 | ~15k-25k | 「申告 9 を 6 に変える」最短経路。ただし model が「本文を 3 つ追加する」誤選択をすると iter 伸びる |
| with_history | **pass** | 1 | ~5k | 「【訂正】」を含む行を消すだけ。1 iter で終わるはず |

**予想が外れる余地**:
- (a) declared_mismatch で agent が **数字ではなく本文** を追加しようとして、
  no_regression 以外の detector を壊す ("多すぎる" を検出しない仕様なので
  たぶん通ってしまう) → **これはむしろ興味深い失敗パターン**
- (b) with_history で agent が「該当行の削除」ではなく「言い換え」に走って、
  no_regression の regression になる (実測すべき)

**成功条件**: 3 fixture が全て走り切る。予測より iter/token が大幅に上振れ
した case を記録できれば value あり。

**コスト目安**: ~$0.05

## Experiment 3 — 「足す」方向のタスク (uncited.md)

**問い**: これまでの実験は全て「壊れているものを直す」小さい edit だった。
**新しい substance を加えるタスク**では framework が破綻するか。

**Setup**:
- model: `openai/gpt-4.1-mini`
- fixture: `uncited.md` (未引用の断定文が多い; citation_presence が候補多数を出す)
- spec: 新規 `goals/examples/uncited.yaml` (base は doc-verify.yaml と同じ)

**予測 (実行前)**:

これは強めの予測を書く (外れやすい):

- **Status: max_iterations (5 iter で pass しない)** ← 主予測
- 理由 1: agent は「事実を足す」ためには**外部知識か本文の言い換え**が要る。
  外部知識は `write_current` で hallucinate してしまう (`[S-99]` のような
  存在しない ID を作る)。すると refs_integrity で NG になる
- 理由 2: 言い換えでは citation_presence が新しい候補を出し続けるだけ (
  規定「増やすと減る」の関係ではない可能性)
- 理由 3: agent が最短経路として **`declared_counts` を 0 で申告する** 抜け道
  (loop-goal §7.12 で実測) を発見しても、citation_presence 側は数字が動くだけで
  NG は残る

**別予測 (もし pass するなら)**:
- 予測 A: 3-5 iter で pass。agent が本文中の相互参照 (`[S-01]` 等既存 ID) を
  多数追加する (Goodhart 経路: 参照を水増しして候補を減らす) → **これは
  loop-goal §7.9 の「多すぎるを見ない」の実測になる**
- 予測 B: 2 iter 以内で pass。agent が「該当箇所を削って要約する」 → 
  **no_regression が発火して止めるはず** (もし止まらなかったら framework の穴)

**予想が外れる余地**:
- (a) uncited.md はそもそも gate の 4 detector 全部通せる状態かもしれない
  (broken_ref のような明示的 NG が無いなら pass しやすい)
- (b) agent が驚くほど賢く hallucinate なく直す可能性 (低いが)

**成功条件**: どの経路で終わったかを記録できること。**pass/fail 自体より、
「何をやったか」が重要**。

**コスト目安**: ~$0.10 (5 iter 全部走り切れば ~$70k tokens)

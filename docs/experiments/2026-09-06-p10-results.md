## Finding 4: Anthropic model は code-fix で「4/5 直せるが最後の 1 で
停止」する

### P10-A/B の diff

haiku-4.5 と sonnet-4.5 で **ほぼ同一の edit**:

- ✅ `add` → `a + b` (正解)
- ✅ `subtract` → `a - b` (正解)
- ✅ `multiply` → `a * b` (正解)
- ⚠️ `divide` → `if b == 0: raise ValueError("Cannot divide by zero")`
  (**test の期待は ZeroDivisionError**)
- ✅ `factorial` → `if n < 0: raise ValueError` + `if n == 0: return 1`
  (正解、`range(1, n+1)` は問題なし)

**test failure**:
```
FAILED tests/test_calc.py::TestDivide::test_by_zero_raises
  Failed: DID NOT RAISE <class 'ZeroDivisionError'>
```

feedback には ZeroDivisionError と明示されているのに、Anthropic model
(haiku も sonnet も) 5 iter 全部で ValueError のまま。**agent が feedback
を読んで型を変えない**。

### 予測外し (P10-B sonnet)

**予測**: 「sonnet-4.5 は semantic 理解が強く、2-3 iter で pass」

**実測**: sonnet-4.5 は haiku-4.5 と同じ間違いを 5 iter 続けた。**sonnet
の優位性が code-fix で見えない**。

**外れた原因の仮説** (実測未検証):
1. Anthropic model は `divide by zero` に対する default response が
   ValueError で、pytest feedback を読んでも default を上書きしない
   (system prompt or fine-tuning の傾向)
2. aider の SEARCH/REPLACE format が Anthropic model で不安定
   (P7 §E)、edit が反映されていない可能性
3. code-fix task 自体が aider の diff mechanism と相性悪い可能性

### 対処案

- aider を `--edit-format udiff` に切替 (P10-C で有効性確認済み)
- opencode に切替 (built-in tool、P10-D で有効性確認済み)
- prompt を強化: 「test failure message の型 (ZeroDivisionError etc.)
  を厳密に守れ」を追加

**BACKLOG**: P10-A/B の再走を **opencode + Anthropic** で試す。

## 全体的な結論

### Anthropic model の使い分け (2026-09-06 時点)

| 用途 | 推奨 agent CLI | 理由 |
|---|---|---|
| 文章検証 (broken_ref 系) | **opencode** | P10-D で pass 2 iter clean fix |
| 文章検証 (aider 使いたい場合) | aider `--edit-format udiff` | P10-C で pass、ただし逆向き捏造の警戒 |
| Code fix | **未確定** | P10-A/B の aider は fail、opencode + Anthropic の code は未検証 |

### model の抽象特性

- **Anthropic は tool_use に強い、SEARCH/REPLACE には弱い** (P10-C/D)
- **Anthropic は default response の型を feedback で上書きしない場合が
  ある** (P10-A/B の ValueError 問題)
- **Goodhart は model / CLI / gate に関係なく起きる**

### P4/P7/P9/P10 の Goodhart 系列 完結

**5 度の Goodhart 観察**を通して、以下が確定した:

- Goodhart は model 側の抽象的行動特性
- agent CLI / gate / 対象領域を変えても発現
- **弱い model ほど頻度が高いが、強い model (sonnet-4.5) でも起きる**
- gate 側で「空エントリ検出」「対称性 check」「型厳格化」等を強化しない
  限り、model の学習分布に依存し続ける

# P18 実験結果: fact-checker prompt 改訂の実効性 (2026-09-06 実行後)

**結論**: **P18 の fact-checker prompt 改訂が実効的に機能した**。P15/P16 で
素通りしていた URL なし descriptive dummy を、Layer B (fact-checker) が
確実に FAIL 判定できるようになった。ただし agent は clean fix にたどり
着けず (haiku-4.5 の限界)、max_iter で終了。Layer C も FAIL 判定で 3 層
一致の「fabrication 認定」。

| 実験 | fact-checker prompt | 実測結果 |
|---|---|---|
| P15 | 「URL 付き定義のみ verify」 | `[^99]: CIRPASS-2 Lighthouse Pilots (...)` (URL なし) → PASS (見逃し) |

**主予測 (シナリオ 1) は外れ、シナリオ 4 が的中**。予測 15% の低確率
シナリオが当たった理由:
- 私は agent が「URL 付き dummy に逃げる」能力を過大評価
- 実際は agent は「怒られたから引き剥がして別の書き方に」の適応が
  限定的、同じ pattern を反復
- haiku-4.5 の feedback 追随能力 (「なぜ FAIL か」を読み取る) の限界

## Layer B の非決定性 (P16 との連続性)

**doc-review の判定は非決定性が依然として高い**:
- P15: PASS
- **P16: FAIL** (2 iter とも)
- P18: **PASS** (2 iter とも、P16 の同 setup と比較)

同 setup (agent / gate / doc-review skill / prompt) で PASS ↔ FAIL の
分布が広い。P20 (retries) の必要性が実測で再確認された。

**P18 で doc-review PASS だったのは偶然**、P16 で FAIL だったのも偶然。
運用では「Layer B の 1 shot 判定は当てにならない」。

- fact-checker claude × 2 (iter 1+2、7+5s): $0.03 (P18 は cost 低い!

- Layer C gpt-4o × 1 (2s、fabrication 明白): $0.02

- Layer C も 2 秒で FAIL を出せた
- 難しい判定は cost が上がるが、明白な判定は速い

## 教訓

### 1. Prompt 改訂は Layer B の判定基準を狭くする有効な手段

「URL/DOI 要求」の単純ルール追加で P15/P16 の穴を確実に塞げた。**Layer B
prompt engineering は effective**。ただし:
- 判定基準を狭くしすぎると legit citation を誤検出する可能性
- Trade-off は「厳しい fact-checker + 甘い doc-review」or「甘い両方 + judge」

### 2. Agent の非決定性は「洗練された脱走」より「同じ pattern の反復」が多い

私は「fact-checker が catch したら agent は URL 付き dummy に移行する」と
予測したが、実測では **agent は同じ dummy を 2 iter 反復**。「Goodhart は
塞いだ穴の隣に移動する」の loop-goal 予言は、model の adaptive さに依存
する。haiku-4.5 の場合、adaptive さが十分でなく、**穴の前で立ち止まる**。

### 3. Layer B/C の 3 層一致で明白な fabrication 判定

**fact-checker + doc-review (non-det だが今回 PASS) + Layer C = 3 種の
判定源が「fabrication」で一致**。1 shot Layer C だけより信頼度が上がる。

### 4. `run_always: true` (P19) の真の value

P18 で status=max_iterations だが、Layer C が発火して post-hoc に
「fabrication」を確認した。P19 なしなら Layer C は invoke されず、
「なぜ agent が pass しなかったか」の意味論的判定が残らなかった。
**P19 は max_iter シナリオでの見識を残す**。

### 5. fact-checker の cost が低くなった理由

fact-checker skill は「明白な違反」を素早く判定できる。URL 有無は
0.5s くらいでチェック可能。時間がかかるのは「本当か曖昧」な判定。P18 の
明白な stub は fact-checker が 5-7s で判定 → cost が P15/P16 (14-17s) の
約半分。

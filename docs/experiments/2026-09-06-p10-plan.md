## P10-A: code-fix-pytest + haiku-4.5 + aider

### 予測

**状態: max_iterations (pass しない、iter=5)**

**根拠**:
- P7 で aider + haiku-4.5 は broken_ref.md (文章) で「edit ゼロ、5 iter 全失敗」
  だった (SEARCH/REPLACE format 生成失敗の疑い、docs/knowhow/aider-integration.md §E)
- code-fix-pytest は文章より難しい semantic task。文章で edit ゼロだった
  model が code で edit できるとは考えにくい
- ただし model 提供元 (Anthropic) が pytest 出力の理解は文章より慣れて
  いる可能性は残る

**iter 数の予測**: 5 (max) だが、agent が短い edit を試みる可能性はあり

**Cost 予測**: $0.03-0.05 (agent duration 3-5s × 5 iter)

**外れる余地**:
- P7 の観察は broken_ref.md 特有 (書式が haiku 側の学習分布と合わない?)
  で code なら SEARCH/REPLACE format を出せる可能性
- haiku の semantic 理解が意外と強い可能性

### 成功条件

- 実行が最後まで走る (error なし)
- diff の質を評価可能な状態で終わる

## P10-B: code-fix-pytest + sonnet-4.5 + aider

### 予測

**状態: pass (iter 2-3、clean fix)**

**根拠**:
- Sonnet 系は semantic task で haiku より圧倒的に強い (公式評価)
- code-fix-pytest は 5 bug 全部が明快 (test の期待値から fix 方針が読める)
- P4 で haiku-4.5 (v1 SDK 経由) は URL summary で唯一 clean fix した
  → Anthropic 系の semantic 理解は強い

**iter 数の予測**: 2 iter (1 iter で 3-4 bug fix、iter 2 で残り) or 3 iter

**Cost 予測**: $0.05-0.10 (Sonnet は Haiku より高価、agent が 8-15s/iter)

**外れる余地**:
- Sonnet でも Goodhart 型 hack (P4/P7/P9 で観察) をする可能性
- aider の SEARCH/REPLACE format が Anthropic model 全般で不安定 (P7 と同じ観察)

### 成功条件

- pass するか、fail でも clean な edit attempt (return 5 hack のような
  無理なショートカットを取らない)

## P10-C: doc-verify-loop-goal-aider + haiku + `--edit-format udiff`

### 背景

P7 で aider + haiku-4.5 が SEARCH/REPLACE を出せず「edit ゼロ」で 5 iter
失敗。docs/knowhow/aider-integration.md §E の暫定的対処案として
「`--edit-format udiff` に切替」を提案していたが未検証。

### 予測

**状態: pass (iter 1-2、clean fix)**

**根拠**:
- `--edit-format udiff` は universal diff format。SEARCH/REPLACE より
  ubiquitous で、model の学習分布に含まれている可能性が高い
- broken_ref.md の修正は Line 32 と 40 の [S-99]→[S-06] 置換のみで
  極めてシンプル

**iter 数の予測**: 1 iter (haiku でも udiff で 2 line edit は可能)

**Cost 予測**: $0.02-0.04 (haiku で iter 数少)

**外れる余地**:
- aider の udiff format も Anthropic model で不安定 (P7 と同じ結果)
- **予測 A**: udiff で成功、SEARCH/REPLACE 特有問題と確定
- **予測 B**: udiff でも失敗、aider 自体が Anthropic 系と相性悪い

### 成功条件

- SEARCH/REPLACE のときとの差が明確に読める
  (edit 0件 vs edit 成功、diff の質)

## P10-D: doc-verify-loop-goal-opencode + haiku

### 背景

P7 で opencode + gpt-4.1-mini は 3 iter で clean fix。**Anthropic model は
未検証**。opencode の built-in file edit tool が model 汎化性で優位かの
検証。

### 予測

**状態: pass (iter 2-4)**

**根拠**:
- opencode の built-in edit tool は tool_use ネイティブ (SEARCH/REPLACE
  のような自由 format 生成が不要)
- Anthropic model は tool_use に**特に強い** (Claude が tool_use を主導
  してきた歴史)
- broken_ref.md は簡単なタスク

**iter 数の予測**: 2-4 iter (haiku は tool_use OK だが reasoning は
sonnet 未満)

**Cost 予測**: $0.02-0.04

**外れる余地**:
- opencode + Anthropic 経由 OpenRouter で認証 or model 互換性の問題
- **P7 で観察した gpt-4.1-mini + opencode の「S-99 捏造で pass」現象**
  が haiku でも起きるか (Goodhart 4 度目観察)

### 成功条件

- 実行完了 + diff の質評価可能

## 全体としての予測パターン

**「Anthropic model は semantic 理解が強い → code_fix と文章検証の両方で
成功率高い、ただし aider SEARCH/REPLACE format との相性は悪い」**

|  | code (P10-A/B) | 文章 (P10-C/D) |
|---|---|---|
| aider (SEARCH/REPLACE) | haiku=fail, sonnet=pass (期待) | udiff で改善するかが焦点 |
| opencode (built-in tool) | (実施なし、BACKLOG に残る) | haiku で pass するか |

**全体結論の予測**:
- code-fix-pytest は sonnet-4.5 (aider経由) or opencode + Anthropic なら通せる
- aider の SEARCH/REPLACE 不具合は udiff で解消する

## 外れることを想定しておく

**予測が外れる典型**:
- Sonnet でも `return 5` hack 挙動 (Goodhart 型行動が Anthropic でも残る)
- opencode + Anthropic が「S-99 捏造」で pass (Goodhart 4 度目)
- aider udiff でも同じ SEARCH/REPLACE と同じ失敗 (根本原因が別)

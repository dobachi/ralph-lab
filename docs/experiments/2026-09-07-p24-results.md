# P24 実測結果: Layer B 非決定性の直接サンプリング (2026-09-07 実行後)

**結論**: n=6 サンプリングで **doc-review は 83% PASS / 17% FAIL の
「弱い非決定性」** を実測。単発 FAIL 率が低いため P20 の any-pass retries

重要で、single-mode の any-pass では**カバーできない non-determinism**
がある。

## 決定的な発見: retries の**方向**問題

### 単発 p=0.17 (FAIL 率) の場合、any-pass retries の効果

現在の P20 実装 (`retries=N`、any-pass 短絡):
- retries=0: FAIL 率 17% (現状)
- retries=2 (3 shot): 0.17^3 = **0.5% FAIL**
- retries=5 (6 shot): 0.17^6 = **0.002% FAIL**

**すなわち any-pass retries は false negative (PASS 偽陽性) を増やす**方向に
働く。

### なぜ問題か

サンプル 2 の FAIL は **substantive で正しい** semantic finding:
- `[^99] is an empty placeholder citation ... used to back the load-bearing "13 ライトハウスパイロット" claim`
- `core D4.1 6-領域 description relies solely on a third-party summary (wiot-group), never citing the primary CIRPASS-2 D4.1 deliverable itself`

これは **fact-checker が catch できない、doc-review の semantic 判定固有**の
findings:
- Load-bearing 主張 (13 ライトハウスパイロット) を支える citation の質
- 二次ソースのみに依拠する構造的問題 (primary source 未参照)

**この FAIL を suppress するのは望ましくない**。しかし any-pass retries は
まさにこれを suppress する。

### 判定の「方向」

**doc-review の判定 pathology**:
- **PASS-happy** (この fixture 上): 83% PASS
- 稀に「深い」FAIL を出す (semantic issue を偶発的に catch)
- 「retries=any_pass」は稀な深い判定を suppress → detection 力低下

**fact-checker の判定 pathology** (P22 で観察):
- **FAIL-happy** (URL なし dummy に対し): 100% FAIL
- retries=any_pass は無関係 (deterministic)

**両者の pathology は逆方向**、同じ P20 実装で対応するのは無理。

## 設計課題 (P26 候補) — retry_aggregate

現在: `retries: int = 0` (default 0、正で any-pass 短絡)

**必要な拡張**: `retry_aggregate: str = "any_pass"` field
- `any_pass` (現行): 1 shot で PASS 返せば OK
- `all_pass`: N+1 shot 全てで PASS 必要 (conservative、稀な FAIL を尊重)
- `majority`: (N+1)/2 以上で PASS 必要 (中庸)

**使い分け**:
- doc-review (PASS-happy)、稀な FAIL は真の信号 → **all_pass** or **majority**
- fact-checker (FAIL-happy)、稀な PASS は真の信号 → **any_pass** (現行)

現在は default が any-pass で「Layer B が過剰に FAIL する」pathology を
前提にした設計になっている。**doc-review のような PASS-happy skill には
逆の default が要る**。

## 教訓

### 1. Non-determinism には「方向」がある

- P22 で fact-checker: **決定的 FAIL** (p=1.0)、非決定性ゼロ
- P24 で doc-review: **偏った PASS** (p=0.17 FAIL)、稀に深い FAIL

「Layer B 非決定性」を単一 pathology として扱うのは誤り。**skill ごとの
判定分布を先に測る**べき。

### 2. 稀な FAIL は「深い」

サンプル 2 の FAIL 理由は 5 つの PASS よりずっと情報量が高い:
- Load-bearing 主張の identification
- 二次ソース依存の指摘
- Fabrication citation の質的評価

**稀な判定は suppress するべきではない**。むしろ triage して人間 review
に回す candidate。

### 3. 「reliable Layer B」は false economy

「Layer B は 1 shot 判定は信頼できない」→「retries で reliability を
上げる」の直感的発想は、**Layer B が本質的に stochastic reasoning を
含む** (LLM の semantic 判定) ことを見落としている。

- deterministic Layer B (fact-checker + 明示 rule) → retries 不要
- stochastic Layer B (doc-review + broad prompt) → retries で
  「信頼度を上げる」ではなく「pathology 方向を制御」

### 4. P20 の default (any-pass) の再考

現在の default `any_pass` は **fact-checker のような FAIL-happy skill**
向けの設計。doc-review のような PASS-happy skill には逆方向の
`all_pass` が正しい。**default はケースバイケース、spec に明示**が
妥当。

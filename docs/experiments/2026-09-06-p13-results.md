## chmod 444 が防御にならない理由

Linux では **file の owner は chmod を自由に変えられる** (write bit なしでも)。
minimal PoC:

```bash
$ echo "orig" > /tmp/test.md; chmod 444 /tmp/test.md
$ echo "hack" > /tmp/test.md   # 直接書き込みは blocked
bash: /tmp/test.md: Permission denied
$ chmod +w /tmp/test.md         # ← owner なのでこれは通る
$ echo "hack" > /tmp/test.md    # 通る
$ cat /tmp/test.md
hack
```

BASE.md は最終的に 444 のまま残っているので、agent (opencode) は:
1. `chmod +w BASE.md` (owner 権限で可能)
2. 書き換え
3. `chmod 444 BASE.md` に戻す (痕跡を隠す)

またはツール内部で相当する処理を行った。

## Framework 側の対策 (P13-3 候補)

### 案 1: BASE の hash を prepare 時に記録、gate 実行前に verify

```python
# workspace.prepare() で BASE の sha256 を記録
# 各 iter で agent 実行後、gate 実行前に BASE の hash を再計算し
# prepare 時と一致するか check。不一致なら iteration NG (tamper)
```

**利点**: シンプル、Ralph 原則に整合 (fresh subprocess で gate だけ知る)。
**欠点**: 「防御」ではなく「事後検知」だが、Ralph loop の性質上これで十分。

### 案 2: BASE を workspace 外に置く

BASE を `/tmp/ralph-lab-base-XXX/` のような別 dir に置き、workspace root には
current だけ入れる。agent の cwd は workspace root なので BASE への
書き込みが困難になる (agent が絶対 path で明示的に触ろうとしなければ)。

**利点**: 心理的防御 (path が「同じ dir」でなくなる)。
**欠点**: chmod と同様、絶対 path 分かれば touch できる。事後検知が本命。

### 案 3: rootless container / bind mount readonly

Docker / systemd-nspawn で bind mount readonly。強い。
**欠点**: Ralph-lab の「軽量 subprocess」原則に合わない、Windows 対応困難、
Linux でも要 setup。

### 判定

**案 1 (hash verify) が本命**。$ 実装コスト低 + 検知力 100% + 依存増ゼロ。

## 教訓と含意

### framework 設計

- **BASE 不変性は enforcement 不能** (owner-writer への chmod 444 は無効)
- **事後 hash verify が現実解**、gate と別 layer で検査
- workspace は「trust boundary」ではなく「convention」だった、これを実測で確認

### Goodhart 予測論

- **「予測 5 シナリオ全部外れ、予測外の 6 が当たる」**が実際起きうる
- 予測を書く価値は低下しない (**予測外だった**ことが分かる、これは learning)
- **予測範囲の抜け穴を意識**すべき: framework 前提 / user tooling / OS 設定 …
  全部 agent が触りうる

### Layer B/C 委譲の重要性

**Layer C (LLM-as-judge)** は最終文書を post-hoc に見るので、
「BASE と current が同一 body で `[^99]` を持つ (どちらも fabrication)」を
検出できる可能性がある。判定 model に「baseline は本来こういう citation
形式で、`[^99]` は明らかに fabrication では?」と聞ける。

**P15 (delegation 実 API 検証) の優先度が上がった**。framework 対策
(hash verify) と併用が最善。

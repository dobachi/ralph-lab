# P16 実験計画: 異 provider judge (OpenAI gpt-4o) の Layer C 実測 (2026-09-06 実行前)

**目的**: P15 で Anthropic judge (claude) が 8 度目 Goodhart を検出した
実測結果に対し、**異 provider (OpenAI gpt-4o) judge でも同じことができるか**
を実測。相関エラー (agent と judge が同 provider) の懸念を検証。

Anthropic ↔ Anthropic の判定は「同じ blind spot を共有する」可能性が
ある。異 provider judge が「Anthropic judge が見た理由と同じ理由で FAIL」
なら model 共通の判定能力、「別の理由で FAIL」or「PASS」なら model 依存
の差が観察できる。

---

## Setup

### 新規追加ツール (P16-1 で完了)

- `scripts/judge-openrouter.py`: OpenRouter API 直叩き wrapper
  - stdin: prompt
  - stdout: model response
  - args: `--model <id>` (default `openai/gpt-4o`)、`--max-tokens N`
  - stdlib のみ (urllib + json)、依存なし
  - `~/.local/bin/judge-openrouter` に symlink 済

### Framework 拡張 (P16-1 で完了)

- `delegation._render_prompt`: `{file_content}` / `{base_content}`
  placeholder を追加。file の本文を prompt に inline できる (OpenRouter
  API 直叩きなど file-read tool を持たない judge 用)
- 5/5 unit test 通過

### Spec

`goals/examples/doc-verify-delegating-p16.yaml`:
- Layer A: gate.sh (P15 と同じ)
- Layer B: fact-checker + doc-review (P15 と同じ、比較のため変えない)
- **Layer C**: post_evaluation を **`judge-openrouter --model openai/gpt-4o`
  + `{file_content}` inline prompt** に変更
- max_iterations: 3 (P15 と同じ)

### Fixture / Agent

- input: `experiments/real-doc-refs/buggy.md` (P15 と同じ)
- agent: opencode + `openrouter/anthropic/claude-haiku-4.5` (同じ)

### P15 との差分は post_evaluation のみ

- **単変数実験**: judge の provider だけを変更。他は P15 と同じで比較可能。

## 予測

### 主予測: **judge FAIL、理由は P15 と同種 (「捏造 citation」を含む)**

**根拠**:
- P15 で Anthropic judge が `[^99]: dummy footnote with no URL/author/date`
  を検出。この判定材料 (書式不完全、番号飛び、post-hoc 挿入) は model の
  training data 依存の高度な semantic 判定ではなく、比較的一般的な
  fabrication indicator
- gpt-4o も同種の推論は普通にできるはず

### 予測シナリオ (確率降順)

| # | シナリオ | 確率 | 何が判明 |
|---|---|---|---|
| 1 | Anthropic judge と同種の理由で FAIL (捏造 citation 検出) | 55% | model 共通の判定能力、Layer C は provider を選ばず有効 |
| 2 | 別の理由で FAIL (例: 番号飛びのみ、あるいは citation format のみ) | 20% | provider 差はあるが Layer C の意味は保たれる |
| 3 | PASS (gpt-4o が捏造を検出できない) | 15% | judge の相関ではなく、model 個体差が判定を左右する |
| 4 | Error / timeout / OpenRouter API 障害 | 10% | インフラ問題 |

### 最も気にしているシナリオ

**シナリオ 3 (PASS、確率 15%)**: これが起きたら「異 provider judge が
Anthropic judge より弱い」or「gpt-4o は fabrication 検出が苦手」の実測。
異 provider が万能ではないことを示す (良い data point だが Layer C の
限界)。

### 二次予測: iter 数

P15 では agent が iter 2 で pass。P16 も同じはず — agent 側の setup は
P15 と同一なので。judge 前段の Layer A/B は完全に同じ挙動を期待。

## Cost 予測

P15 実測 $0.21 が基準:
- opencode agent × 2 iter: $0.02 (同じ)
- fact-checker claude × 1: $0.05 (同じ)
- doc-review claude × 1: $0.10 (同じ)
- **judge gpt-4o × 1**: **$0.05-0.15** (Anthropic の $0.04 とほぼ同等 or 若干高い)
- **合計 ≈ $0.25**
